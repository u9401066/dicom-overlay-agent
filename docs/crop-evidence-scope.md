# 裁圖證據的範圍與合併

全圖判讀與局部細看是不同的觀察範圍。例如，細看 V3–V5 的裁圖時，模型說
「V1 不在圖內」，不代表原始 ECG 缺少 V1。不能將這類局部限制直接當成全圖
影像品質的事實。

## App 的合併契約

`apply_refinement_delta` 對 `add`、`confirm`、`revise` 的裁圖 notes 與理由加上
`[Crop-only evidence; ROI x=… y=… w=… h=…]` 前綴。

- 範圍來自 App 實際送入該次細看的裁圖，使用原始、已去識別 ROI 的 0–1 座標，
  不是螢幕座標，也不是模型猜測的導程名稱。
- 顯示座標取小數四位供人辨識；精確座標與原始理由仍留在 `analysis_trace`
  的 refine 記錄。bbox 的 crop→ROI 映射不受文字格式影響。
- 保留既有全圖 notes；裁圖文字不能覆蓋它。相同裁圖的重複文字去重，不同
  裁圖說出相同內容則分別保留範圍。空白文字不新增空標籤。
- 不在指定 target 邊界內的修改仍被拒絕；無定位的新增 finding 仍須通過原本
  的 provenance 契約。文字前綴不能替代工具的框驗證收據。

這是 provenance 修正，沒有改動 16-key 結果 schema、診斷標籤、嚴重度、原本的
detail 更新邏輯、bbox、ROI、模型提示模板或請求數。`notes` 仍是普通文字陣列，
可供原有報告面板與 JSON 匯出使用，並不引入新的相容層或執行依賴。
後續報告整合回合會看到帶範圍的 notes，故不主張模型輸出與修改前完全相同。

## 驗證與限制

2026-09-10 的實機批次暴露了裁圖限制文字缺乏 scope 的問題。以不含病例答案
的合成資料建立回歸：修改前 9 項失敗，修改後 10 項 scope 測試與 139 項既有
multi-pass 測試通過。測試覆蓋三種 action、無 payload 的確認、空白與重複、
不同裁圖、語意-only 新增及 target 邊界。

完整 unit／smoke／mock integration 回歸為 **1,393 通過、6 略過**；略過項目為
worktree 未放置的 portable Node／本地 frozen cohort，以及需 opt-in 的封裝／
原生螢幕擷取驗收。新 worktree 最初缺少 OpenClaw，5 項 native plugin 測試
失敗；補裝 lockfile 固定版後全部通過，沒有將失敗改為略過。另驗證 Qt 報告
保留完整註記、不壓縮換行文字，以及 JSON 匯出保留同一 notes 陣列。合成
離屏預覽經字型載入後目視檢查；這不是新的真實模型案例或原生桌面驗收。

這不會自動糾正模型對原圖的錯誤認知，也不會判定哪些導程真正可見。原始
全圖若已誤判缺少導程，仍需影像／導程驗證與人工覆核。這項修正未套用到
正在進行的 frozen Astra 實機批次；必須另跑候選版 GUI 與不完整 ECG 配對
驗收，才能聲稱實際判讀或使用體驗改善。
