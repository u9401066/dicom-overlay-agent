MVP：人工檔案維護與審查

  1. 找到規則，展開人用步驟、agent 步驟、來源及完整欄位，記下 rule ID 與 digest。
  2. 使用每條規則的「在 GitHub 網頁編輯此來源檔」連結；登入 GitHub，修改 canonical YAML，建立分支並提出 Pull Request。多條規則可能共用一份檔案。
  3. 同步再生 human／agent／runtime views，由具相關專科資格的 reviewer 檢查臨床內容，並通過 schema、規則測試與 SQLite parity。不要只修改生成頁面或複核日期。
  4. 經審查合併 main 後，Pages 自動重建目錄；驗證失敗則不發布新版。App 規則仍須透過另外驗證的軟體版本更新。

這是靜態網站的 GitHub 審查維護入口，不是在此頁直接儲存的管理後台；網站不收集 GitHub token、不寫入臨床執行中的資料庫。GitHub 編輯入口開啟的是最新 main，提交前請核對差異。
