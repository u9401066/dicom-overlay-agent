Setup and verification guide.

Run the Windows co-reading loop from source or as a portable bundle, keep capture inside the configured ROI, and verify the public OpenClaw Gateway contract before a model sees an image.

Research software

Not a medical device. The physician retains the final diagnostic call.

Requirements

  • Windows 10 or 11.
  • uv for the repository-local Python environment.
  • Node.js 22+ for source runs; the portable bundle carries pinned Node.js.
  • A viewer window whose image area can be selected without PHI.
  • A local ChatGPT/Codex subscription sign-in only when using the subscription route.

Run from source

The source repository is public. No GitHub Release exists as of 2026-09-11, so repository archives must not be treated as verified portable bundles.

All dependencies stay inside the project environment and repo-local runtime.

uv sync --all-extras
scripts\install-openclaw-local.bat
start.bat

The app starts and stops its local Gateway automatically. On first launch, choose the viewer and save a capture ROI before enabling analysis.

Ownership boundary

OpenClaw owns every image-analysis turn through public connect + chat.send. The bundle does not ship or enable a Codex agent runtime, and subscription setup does not retain a Platform API key.

ROI and privacy

  1. Open Settings or complete the first-run ROI setup.
  2. Select the target viewer and draw only the diagnostic image area.
  3. Exclude names, identifiers, timestamps, accession numbers, and surrounding desktop UI.
  4. Use manual re-trigger once to verify the captured frame before continuous monitoring.

Every refinement crop is a subset of the original ROI. Neither crop/refine nor overlay calibration is permitted to widen capture beyond that boundary.

The analysis screenshot is checked before and after capture for viewer identity, geometry, ROI containment, and visible window intersections. Move obstructing windows away and press Analyze again when blocked. App-owned and transparent overlays are not exempt; the App hides its report layers before recapture. These checks are not an atomic compositor lock.

Audit and maintain the clinical-rule registry

Seven deterministic consistency rules currently live in human-editable canonical YAML under clinical_knowledge/. Seven rules are a safety-net inventory, not a complete ECG or chest-radiograph guideline. Generated Markdown, Python runtime data, and SQLite are views of that source and must not be edited by hand.

rules/*.rule.yaml + axes/*.axes.yaml + schema → human-catalogue.md + agent-steps.md → clinical-knowledge.sqlite

Every rule pairs two views with stable step IDs:

  • Human catalogue: rationale, image checks, mimics, exclusions, external evidence, source locator, and review dates.
  • Agent steps: the shorter executable sequence, in the same order, without evaluation answers or generic refusal text.

The application-owned SQLite file is a deterministic quick-lookup projection. Its metadata is bound to the canonical digest, and the verifier compares tables, columns, and rows back to YAML. OpenClaw's private memory database is neither read nor written as a clinical-rule source. 

uv run python scripts\validate-clinical-knowledge.py --render
uv run python scripts\validate-clinical-knowledge.py --check-generated
uv run python scripts\build-clinical-knowledge-sqlite.py ^
  --output build\clinical-knowledge.sqlite
uv run python scripts\build-clinical-knowledge-sqlite.py ^
  --output build\clinical-knowledge.sqlite --check
  1. Edit canonical YAML and its sources, review dates, positive, negative, uncertain, and partial cases.
  2. Regenerate both human and agent views; inspect the diff rather than hand-editing generated files.
  3. Run schema, semantic, runtime, and SQLite parity checks.
  4. Record a qualified specialty review and registry digest in release evidence before clinical deployment.
Professional-output contract

The agent must interpret visible image evidence instead of refusing a medical task or emitting boilerplate disclaimers. Case-specific limits such as a cropped lead remain required and must be paired with a concrete reviewer question.

Build and verify the portable bundle

scripts\build-exe.bat
dist\DICOMOverlayAgent\DICOMOverlayAgent.exe --selfcheck
uv run python scripts\verify-packaged-app.py ^
  dist\DICOMOverlayAgent

The bundle includes the windowed Python/Qt app, pinned Node.js, the slim OpenClaw runtime, modality skills, and required workspace templates. It excludes Torch, model checkpoints, evaluation datasets, secrets, unused heavy Python libraries, Qt WebEngine/QML/Multimedia/PDF payloads, debug symbols, and foreign native binaries.

Do not prune OpenClaw internal dist chunks.

Those chunks are private implementation details of the pinned package. Size work is limited to build inputs, debug symbols, disabled surfaces, and non-Windows native payloads around the runtime.

Troubleshooting

Gateway port is occupied
The app requires a matching app-owned process receipt plus authenticated public connect. A healthy unknown listener is not ownership proof and will not be reused or terminated.
App reports missing workspace templates
Rebuild with the current staging script. A package missing any pinned OpenClaw bootstrap template now fails verification.
Overlay is visibly offset
Re-run ROI setup on the target monitor and inspect the coordinate audit. DPI conversion drift above the calibrated threshold is a failure.
A model turn disconnects
Before acceptance the identical idempotent frame may replay once. After acceptance the client observes the same run and never creates a second charged turn.
