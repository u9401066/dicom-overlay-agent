Requirements

  • Windows 10 or 11.
  • uv for the repository-local Python environment.
  • The documented checkpoint uses Node.js 24.18.0; use the repository's verified portable download rather than an unrelated system Node version.
  • A viewer window whose image area can be selected without PHI.
  • A local ChatGPT/Codex subscription sign-in only when using the subscription route.

Run from source

The source repository is public. No GitHub Release exists as of 2026-09-29, so repository archives must not be treated as verified portable bundles.

These instructions describe the development branch, not the older App on main. The documented source checkpoint is 1a7cb81. The separately verified 36dc3c6 executable does not include its later Viewer-recovery change. All dependencies stay local; use a fresh clone, not a recorded test runtime.

git clone --recurse-submodules --branch agent/viewer-publication-recovery-20260929 ^
  https://github.com/u9401066/dicom-overlay-agent.git
cd dicom-overlay-agent
git checkout --detach 1a7cb81c90f25ac41c1c568c911389d39231cc01
git submodule update --init --recursive
uv sync --locked --all-extras
powershell -NoProfile -File scripts\fetch-node.ps1
scripts\install-openclaw-local.bat
start.bat

The app starts and stops its local Gateway automatically. On first launch, choose the viewer and save a capture ROI before enabling analysis.

ROI and privacy

  1. Open the image in your viewer or browser, then Settings → Choose image window.
  2. Select the exact source window and draw a fresh ROI containing only the diagnostic image area.
  3. Exclude names, identifiers, timestamps, accession numbers, and surrounding desktop UI.
  4. Use manual re-trigger once to verify the captured frame before continuous monitoring.

Explicit window selection pins its identity for this App session, never silently falls back to another window, and does not overwrite another viewer's saved ROI. Closing/restarting the source requires reselection and a fresh ROI. One exposed browser-image workflow has source-App evidence, not broad third-party viewer or cross-monitor acceptance; the picker alone is not proof of successful analysis.

Every refinement crop is a subset of the original ROI. Neither crop/refine nor overlay calibration is permitted to widen capture beyond that boundary.

The analysis screenshot is checked before and after capture for viewer identity, geometry, ROI containment, and visible window intersections. Move obstructing windows away and press Analyze again when blocked. App-owned and transparent overlays are not exempt; the App hides its report layers before recapture. These checks are not an atomic compositor lock.

Mark and ask about one image region

Analyze the current ROI first. Manual Mark covers its blank image areas as well as AI boxes, not the whole desktop. Each region has its own conversation for the current image.

  1. Existing AI marker: use Inspect on the marker to open its question dialog or completed history.
  2. New region: choose Mark and drag inside the ROI, including blank space outside AI boxes; submit a question about that crop.
  3. Continue: type in the regional panel and press Send. Hide closes only the panel; Inspect reopens completed history without another model request.
  4. Review a proposal: an answer does not change the report. Use Apply to report only after reviewing it, or dismiss the suggestion.
  5. Keep a record: Export writes the image-bound result and regional-conversations.json. History is not automatically saved or restored after restart.

The model receives at most six recent pairs within a 12,000-character context budget; full completed history remains readable/exportable. A new image or fresh analysis clears its old review context.

Each structured regional question includes the selected crop and the same original authorized ROI as context, not a fresh screenshot or the full desktop. Answers must distinguish evidence inside the box from surrounding leads or labels. Context does not bypass small-crop, calibration or explicit-approval gates.

This opt-in development mode is separate from the legacy default launch path. Only use the deidentified-input assertion after verifying that the selected image and ROI contain no patient identifiers; the flag does not deidentify an image for you.

start "" ".venv\Scripts\pythonw.exe" -m dicom_overlay ^
  --config config.yaml --scientific-review --deidentified-input
  1. Quality gate: establish visible content and whether interpretation is possible.
  2. Blind pass: retain observations before reconciliation.
  3. Independent evidence: bind source-localized evidence and native geometry receipts.
  4. Reconciliation: resolve conflicts without treating a coordinate receipt as clinical confirmation.

Audit and maintain the clinical-rule registry

Seven deterministic consistency rules currently live in human-editable canonical YAML under clinical_knowledge/. Seven rules are a safety-net inventory, not a complete ECG or chest-radiograph guideline. Generated Markdown, Python runtime data, and SQLite are views of that source and must not be edited by hand.

rules/*.rule.yaml + axes/*.axes.yaml + schema → human-catalogue.md + agent-steps.md → clinical-knowledge.sqlite

Every rule pairs two views with stable step IDs:

  • Human catalogue: rationale, image checks, mimics, exclusions, external evidence, source locator, and review dates.
  • Agent steps: the shorter executable sequence, in the same order, without evaluation answers or generic refusal text.

The application-owned SQLite file is a deterministic quick-lookup projection. Its metadata is bound to the canonical digest, and the verifier compares tables, columns, and rows back to YAML. OpenClaw's private memory database is neither read nor written as a clinical-rule source. 

uv run python scripts\validate-clinical-knowledge.py --render
uv run python scripts\validate-clinical-knowledge.py --check-generated
uv run python scripts\build-clinical-knowledge-sqlite.py ^
  --output build\clinical-knowledge.sqlite
uv run python scripts\build-clinical-knowledge-sqlite.py ^
  --output build\clinical-knowledge.sqlite --check
  1. Edit canonical YAML and its sources, review dates, positive, negative, uncertain, and partial cases.
  2. Regenerate both human and agent views; inspect the diff rather than hand-editing generated files.
  3. Run schema, semantic, runtime, and SQLite parity checks.
  4. Record a qualified specialty review and registry digest in release evidence before clinical deployment.

It excludes Torch, model checkpoints, evaluation datasets, secrets, unused heavy Python libraries, Qt WebEngine/QML/Multimedia/PDF payloads, debug symbols, and foreign native binaries.

Do not prune OpenClaw internal dist chunks.

Those chunks are private implementation details of the pinned package. Size work is limited to build inputs, debug symbols, disabled surfaces, and non-Windows native payloads around the runtime.

Troubleshooting

Mark only starts on an AI box
The old Windows overlay let clicks pass through fully transparent blank pixels. The candidate has an almost-transparent input surface over the authorized ROI in Mark mode. Confirm your exact build; main and an older installed EXE are not updated by reading this guide. ROI edges still limit selection.
Viewer minimized while analysis is finishing
The later source can wait within the original deadline for the same window. Restore that window without changing its image. It must pass identity, geometry and pixel checks before publication; it will not resend merely to recover a draft. The real canary is only partially accepted, and this fix is not in the 36dc3c6 EXE.
Need to use the desktop during a recorded run
Pause before switching cases. Closing the App before Export can leave no canonical export or screenshot, even after visible publication. Do not restart a recorded runtime in place: startup can truncate its logs. Preserve failures and use a fresh runtime for a newly declared attempt.
Gateway port is occupied
The app requires a matching app-owned process receipt plus authenticated public connect. A healthy unknown listener is not ownership proof and will not be reused or terminated.
App reports missing workspace templates
Rebuild with the current staging script. A package missing any pinned OpenClaw bootstrap template now fails verification.
Overlay is visibly offset
Re-run ROI setup on the target monitor and inspect the coordinate audit. DPI conversion drift above the calibrated threshold is a failure.
A model turn disconnects
Before acceptance the identical idempotent frame may replay once. After acceptance the client observes the same run and never creates a second charged turn.
